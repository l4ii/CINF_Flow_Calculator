# “了解我们”三页面重置设计

日期：2026-08-19

## 目标

参考 `D:\软件\CINF_RockMass_Calculator` 中的公司介绍、科研创新中心和矿山事业部页面，重置当前流量计算软件的“了解我们”三页面。

三个页面统一使用参考工程的标题体系和视觉骨架：

- `ABOUT / 01`：公司介绍
- `ABOUT / 02`：科研创新中心
- `ABOUT / 03`：市政事业部
- 页面正文分节统一使用 `SECTION / NN` 标题

公司介绍和科研创新中心直接迁移参考工程的内容与页面结构。第三页不使用参考工程的矿山事业部内容，而是沿用其一致性结构，填充当前工程已有的市政事业部资料。

## 实施范围

### 页面组件

在当前工程中引入独立的“了解我们”页面组件，避免继续扩张 `MainContent.tsx`：

- `AboutPage.tsx`：根据 `aboutDepartment` 分发公司、科研和市政页面。
- `AboutDesignPrimitives.tsx`：提供统一的 `AboutPageHero` 和 `AboutSectionHeading`。
- `MunicipalAboutPage.tsx`：承载市政事业部独立页面及其图片交互。

`MainContent.tsx` 保持计算模块职责，仅在 `currentView === 'about'` 时渲染新的页面组件。现有公式计算、结果展示、导出、许可证、设置和助手逻辑不改变。

### 资源目录

将页面资源整理为与参考工程一致的分组：

- `frontend/public/about/cinf`：公司介绍图片。
- `frontend/public/about/rdc`：科研创新中心高清图片和缩略图。
- `frontend/public/about/2`：市政事业部手册及工程图片。

公司和科研资源从参考工程复制。市政资源使用当前工程 `frontend/public/municipal` 中现有的 `doc-image01.jpeg` 至 `doc-image20.jpeg`，迁移到 `about/2`。旧资源仅在确认无其他引用后再移除；本次优先保证新页面路径可用，不扩大清理范围。

## 页面设计

### 公司介绍

直接迁移参考工程的公司介绍页面：

- Hero 标题为“有色金属全产业链技术与服务提供商”。
- 使用 `ABOUT / 01` 标识。
- 展示企业标签、公司主图和四项核心数据。
- 使用 `SECTION / 01` 展示发展历程与组织沿革。
- 使用 `SECTION / 02` 展示公司与业务联系方式。
- 保留暗色模式和中英文界面适配。

### 科研创新中心

直接迁移参考工程的科研创新中心页面：

- Hero 标题为“科研创新中心”。
- 使用 `ABOUT / 02` 标识。
- 展示创新平台建设、成果转化、标准与知识产权、产学研用协同四项标签。
- 使用 `SECTION / 01` 展示五个省级创新平台。
- 每个平台继续使用交替图文布局、缩略图优先加载和点击放大。
- 保留暗色模式和中英文界面适配。

### 市政事业部

市政页沿用参考工程事业部页面的层级，不复制矿山业务内容：

- Hero 使用 `ABOUT / 03`，眉题为“长沙有色院 · 市政事业部”，主标题为“市政工程”。
- 摘要聚焦废水处理与矿浆输送技术。
- Hero 标签覆盖工程咨询、工程设计、EPC 总承包、科研与技术开发。
- 首屏数据条使用能够由现有材料支持的业务信息，不引入未经现有资料确认的矿山数据。
- `SECTION / 01`：业务概览与市政事业部宣传手册轮播。
- `SECTION / 02`：废水处理技术，包含采选废水和冶炼废水。
- `SECTION / 03`：矿浆输送与市政污水处理能力。
- `SECTION / 04`：代表性工程和相关资质。
- 保留现有手册轮播、图片点击放大、键盘 Escape 关闭和图片懒加载。

## 导航与状态

侧栏继续使用现有的 `cinf`、`research`、`municipal` 标识，不改变 App 层状态协议：

1. 用户点击侧栏条目。
2. `App.tsx` 设置 `currentView = 'about'` 和 `aboutDepartment`。
3. `MainContent.tsx` 将 `darkMode`、`language`、`aboutDepartment` 和返回回调传给 `AboutPage`。
4. `AboutPage` 渲染对应页面。

侧栏显示名称统一为：

- 长沙有色冶金设计研究院有限公司
- 长沙院科研创新中心
- 长沙院市政事业部

页面切换时滚动位置回到顶部；离开含灯箱的页面时关闭灯箱，避免跨页面残留遮罩。

## 交互与错误处理

- 图片加载失败时，科研缩略图回退到高清原图。
- 图片灯箱提供可见关闭按钮、背景点击关闭和 Escape 关闭。
- 所有可点击图片提供明确的 `aria-label` 和替代文本。
- 组件未知 `aboutDepartment` 时不渲染错误业务内容，返回空状态或安全占位。
- 迁移后所有图片路径使用相对路径，兼容 Vite 开发环境和 Electron 的 `file://` 打包环境。

## 视觉约束

- 三页共用同一个 Hero 与分节标题组件，保证编号、字重、间距、边框和颜色一致。
- 页面使用当前应用的蓝色强调色、浅灰背景和暗色模式配色，不引入新的主题体系。
- Hero 和内容区避免嵌套卡片；信息卡仅用于独立数据或可交互内容。
- 宽屏使用双栏或多栏布局，小屏自动降为单栏；标题和按钮不得溢出或遮挡。
- 保持当前应用顶部标题、侧栏和助手入口，不复制岩体分级工程的产品文案。

## 验证标准

### 静态验证

- TypeScript 编译通过。
- Vite 生产构建通过。
- 页面资源路径在构建产物中可解析。
- 不修改当前已有的 `requirements.txt` 和 `requirements_win7.txt` 用户改动。

### 浏览器验证

- 公司、科研、市政三个侧栏入口均可打开正确页面。
- 三页依次显示 `ABOUT / 01`、`ABOUT / 02`、`ABOUT / 03`。
- 所有分节标题使用统一的 `SECTION / NN` 形式。
- 公司和科研内容与参考工程一致。
- 第三页仅展示市政事业部内容，不残留矿山事业部名称、项目或人员。
- 科研平台图片、市政手册轮播和图片灯箱可正常工作。
- 在桌面和移动宽度下检查首屏布局、文字换行、图片比例和遮罩层。
- 检查浏览器控制台无新增错误。

## 非目标

- 不改变计算公式、计算流程、后端接口或计算导出。
- 不改造设置页、许可证页或助手业务逻辑。
- 不将岩体分级工程的产品标题、方法导航或矿山业务内容带入当前工程。
- 不进行与“了解我们”页面无关的大范围代码格式化或资源清理。
